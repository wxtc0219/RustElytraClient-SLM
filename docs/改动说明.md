# 改动说明（技术细节）

本版（v1.0.0 多版本）**不再使用 ASM 字节码补丁**，改为**源码级补丁**：

- REC 1.21.1 / 1.21.4：直接取上游对应分支的 beta1.6 源码，加入第 4 模式后重新编译
- REC 1.21.11：取上游 1.21.8 分支（baritone 版）源码，先移植到 1.21.11 API，再加第 4 模式
- MagicBaritone 1.21.4 / 1.21.11：取 baritone 官方对应分支源码，重新应用 MagicBaritone 的甲飞补丁后编译

对应补丁：
- `patches/rec/*.diff` — 三个版本的 REC 源码 diff（相对上游分支）
- `patches/magicbaritone/*.diff` — 两个 MagicBaritone 移植版 diff（相对 baritone 官方分支）
- `tools/patch_rec_slm.py` — 一键给 REC 源码打第 4 模式补丁的脚本

## 一、REC 第 4 模式（三版本一致）

### 1. `TaskThread.TaskType` 新增枚举 + `isSlm()`

```java
public enum TaskType {
    EXP_BOTTLE, ELYTRA, INFINITY_ELYTRA, SLM_TAKEOVER
}

public static boolean isSlm() {
    TaskThread t = ModThread;
    return t != null && t.type == TaskType.SLM_TAKEOVER;
}
```

### 2. 菜单第 4 个按钮

`RSTScr.ciScr` 的 `SrcEntry[]` 长度 5 → 6（`ciButtonsRow` 5 → 6），
新增按钮「开始飞行(SLM甲飞接管)」，点击后
`TaskThread.StartModThread(TaskType.SLM_TAKEOVER, ...)`。

### 3. 补给逻辑复用「无尽鞘翅」分支

`RustSupplyTask.SupplyTask()` 内两处 `switch (type)`：

- `FireworkInNeed`：`case SLM_TAKEOVER` → 目标 1664 个烟花（26 组）
- 可替换快捷栏槽位统计：`case SLM_TAKEOVER` → 26 组

### 4. 其它模式行为不变

- `RustElytraTask.ElytraTask`：`INFINITY_ELYTRA` 分支的 `elytraAllowEmergencyLand=false`
  同样适用于 `SLM_TAKEOVER`
- `RepairElytra`（仅 XP 模式调用）不受影响；`ElytraChecker`（仅 ELYTRA 模式调用）不受影响
- `RustSupplyTask.SortAndCheckInv` 的“必须穿戴耐久3经验修补鞘翅”检查：
  `if (!elytra && !TaskThread.isSlm()) throw ...`

### 5. 起飞逻辑（SLM 专用）

原版 `FlightStatusCheck` 的自动起跳用 `TimelinessCounter(100)`（100 tick 滑动窗口）计数，
起飞连续失败时窗口会漏空 → 经常要卡 5 分钟才走「烟花起飞」分支。

SLM 模式改为持久计数 `slmTakeoffFails`：

- 失败 < 3 次：`slmElytraTakeoff()`（按住空格起跳 → 空中再补一次触发甲飞滑翔，重试 3 轮）
- 失败 ≥ 3 次：`flyToOpen()`（烟花起飞）
- 成功（`isGliding()` 或离地）后计数清零

> 1.21.1 的 yarn 方法名是 `isFallFlying()`，1.21.4/1.21.8 是 `isGliding()`，脚本里已自动识别。

### 6. 容器标题宽松匹配 + 等待时间

- `ContainerScreenChecker`：`equalsIgnoreCase` → `containerNameMatches()`
  （去掉 `§` 颜色码、空格、双向包含，兼容服务器/插件改容器名）
- `WaitForScreen`：循环 20 → 120 tick

## 二、顺带修好的老 bug

### A. `无可用熟猪排!` 导致整段任务失败

`SupplyTask` 中「末影箱里找食物最多的潜影盒」找不到时原本 `throw`，
现在只发 warning，用身上现有食物继续：

```java
if (slot2 == -1)
    MsgSender.SendMsg(client.player, "末影箱里没有" + Food.getName().getString() + "，先用身上现有的食物继续", MsgLevel.warning);
else ShulkerList.add(slot2);
```

### B. `挖掘异常？取消挖掘`（挖补给盒 2 秒超时）

`mineSupplyShulker` 原本：调用 baritone `MineProcess` 后最多等 **40 tick（2 秒）**，
超时就 `throw`。服务器卡顿/反作弊回弹时必炸。

修改为：

1. 挖之前先 `client.setScreen(null)` 关掉潜影盒界面（界面开着时无法攻击方块）
2. 等待放宽到 **600 tick（30 秒）**
3. 超时后取消 baritone 挖掘，**自己用手挖兜底**（方块是自己刚放的，在交互距离内）：
   把视线转向方块，每 tick `updateBlockBreakingProgress` + `swingHand`
4. 再等最多 60 tick 等物品拾起

## 三、1.21.11 移植要点

REC 1.21.8 分支源码 → MC 1.21.11，主要 API 变化：

| 1.21.8 写法 | 1.21.11 写法 |
| --- | --- |
| `Entity.getPos()` | `Entity.getEntityPos()` |
| `Entity.getWorld()` | `Entity.getEntityWorld()` |
| `new KeyBinding(..., "分类")` | `KeyBinding.Category.create(Identifier.of(...))` |
| `PlayerInventory.main`（private） | `inventory.size()` / `inventory.getStack(i)` |
| Fabric `WorldRenderEvents` | 新渲染 API 大改 → **轨迹预览渲染暂时停用**（`TrajectoryRenderer` 改为空实现） |

## 四、MagicBaritone 1.21.4 / 1.21.11

Alastorbaby 的甲飞补丁相对 baritone 的改动集中在：

1. `api/Settings.java`：新增 `slimePhysics`、`slimeGroundClearance`、`slimeSideClearance`、`slimeScanNodes`
2. `command/defaults/SlimeCommand.java`：`#slime true|false` 切换并持久化到 settings.txt
3. `process/elytra/ElytraBehavior.java`：甲飞驾驶核心（`tickSlimeControl`、方向探测、按键状态、假朝向）
4. `process/ElytraProcess.java`：接管模式下不自动降落/不因烟花不足拒绝起飞
5. `behavior/LookBehavior.java`：接管模式下不再碰实体朝向
6. launch mixins：`MixinKeyMapping`（接管 6 个移动键）、`MixinLocalPlayerViewRestore`（还原真实视角）、
   `MixinMinecraft`（tick 末尾兜底还原假朝向）

移植时用 3-way merge 把这些改动应用到 baritone 官方分支，并适配了 baritone 1.21.4/1.21.11
的 `NetherPathfinderContext` 新 API（`npfContext` 字段 + `IElytraPathFinder`）。
